# Personal Google connector (source integration; no deployment)
Use a Google Cloud OAuth web client with Gmail, Calendar and Drive APIs enabled. Register the Worker HTTPS origin plus /v1/assistant/google/callback as an authorized redirect URI. Add your Google account as a test user if the app is in Testing. Set the three connector credentials/settings described in wrangler.toml, apply migration 0004 after 0002/0003, and explicitly enable ASSISTANT_GOOGLE_ENABLED. Google testing-mode refresh grants may expire after seven days; production verification is separate.
The same DOMINION Google subject must approve. One-time state and PKCE, encrypted account-bound refresh credentials; no token reaches mobile. Read-only: latest 5 inbox headers, next 10 primary calendar events, 10 recent Drive filenames. User can disconnect. This is a real API execution route, not browser automation, not a general autonomous background executor. No automated purchases, outbound mail or login bypass. OAuth flow must be tested with the real configured account. Existing main is untouched.

Migration 0005 adds bounded durable Google read jobs. Jobs wait for authorization, resume on OAuth callback and existing scheduled trigger, lease execution to avoid concurrent duplicates, encrypt results, expire after 24h, and allow cancellation. This is Google-only, not a general browser executor. The initiating app grant must remain valid to execute. Results are retained up to 30 days; no automatic external write action. Mobile fetches results on foreground. Real-account acceptance test still required.

### Mail monitoring (migration 0008)
Opt-in monitoring uses Gmail history and metadata, not model calls or full email bodies. Start establishes a new history baseline. All inbox mail, Gmail IMPORTANT label, or literal sender/subject filter; category shown from Gmail's existing labels. Existing 15-minute scheduled Worker checks changes, manual check is limited to once per minute. Cursor updates and encrypted alerts are committed in one D1 batch under the active grant and lease. If Gmail history expires or one page exceeds 20 IDs, monitoring pauses visibly for explicit resync; no claim of lossless recovery. Results retained 30 days and the mobile app pulls them on foreground/notification. Push sends only a generic notice; Expo credentials required, delivery not guaranteed. No automatic archive, delete, label modification or reply. A revoked/expired app grant stops monitoring until restarted. New jobs also notify opt-in devices on completion or human intervention. Set ASSISTANT_MAIL_WATCH_ENABLED=1 only after migration and Google configuration. No deployment performed.
