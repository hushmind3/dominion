# Independent browser worker
This implementation uses the September 2026 Browser Run native session binding and CDP over the session-pinned WebSocket. No npm browser dependency and no end-user key. The Cloud branch is independent of production main.
Apply migration 0007 after 0004–0006. Enable Browser Run and set ASSISTANT_BROWSER_ENABLED=1 and ASSISTANT_BROWSER_DAILY_LIMIT=2. Configure explicit verified identity dependencies with ASSISTANT_BROWSER_EXTRA_HOSTS only if required by a site. The trial is limited to one active browser job per account, 4 minutes and 16 model decisions. Provider usage limits still apply. Disable the feature to stop new jobs.
A job is started only after the user confirms the site and goal. The Durable Object alarm runs a bounded observe-plan-act loop without the handset remaining open. User handoff uses Cloudflare.handoff, short-lived Live View URL and getHandoffState; on exit it reinspects the page, not blindly declaring authentication success. Button actions require exact user approval; uncertain side effects are never retried. Only fixed DOM/CDP operations are available, no arbitrary model JavaScript. Completion requires text evidence from the actual observed page. All page content is untrusted; credential fields trigger manual handoff.
Not yet supported: persistent authenticated browser profiles between jobs, complex multi-tab/iframe login, downloads/upload artifacts, arbitrary domain-dependency discovery, screenshot reasoning or site-specific proven workflows. Some websites may block automated browsers. The mocked tests exercise the orchestration, not live government websites. Test on a harmless site, then personally approved read-only real site before any submission. Do not enable session recordings for private work.

Approval now includes a bounded page preview and a fingerprint of the exact observed URL, page text and target. A changed page invalidates the approval and re-plans instead of clicking. Authentication fields are detected before truncating the visible control list. Tests cover handoff pause, live-link non-persistence and re-observation after completion.

## Private browser vault
Set BROWSER_VAULT_SECRET to a strong random secret (at least 32 characters). Each job can explicitly opt in to site-scoped HTTPS cookie reuse, stored encrypted for up to 24 hours. Only cookie data from that site's own domain is restored, before navigation; third-party identity-provider cookies and partitioned cookies are excluded. No password extraction or CAPTCHA bypass. Sites may invalidate cookies and require fresh authentication. The user can delete a site's stored profile, which also ends any active job on that site. The vault supports approved same-origin GET PDF links (original bytes; rejects redirects and non-PDF) and separately labeled print-to-PDF page snapshots. Max 2 MiB per document, two per job and five recent documents per account, access expiry seven days; expired entries are pruned on subsequent jobs. Document bytes are encrypted, hashed, and returned only to the authenticated account. Not a generic browser filesystem or official-document issuance guarantee. Actual site downloads via POST/blob/print popup and file upload remain unsupported.

## Explicit file attachment
A visible empty HTML file input can request a user-selected file. The browser task pauses until the user confirms an actual PDF/JPEG/PNG (max 2 MiB), checks signature and accepted types, then re-observes the exact page/target fingerprint before assigning a browser File via DataTransfer. Bytes go only to the fixed browser operation and are not persisted in job records or sent to the LLM. This does not claim a successful website upload: subsequent page inspection must confirm the result. Custom hidden file inputs, drag-and-drop widgets and sites rejecting synthetic input events may need manual handoff. Live testing remains required.
