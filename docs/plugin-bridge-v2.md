# DOMINION plugin SDK v2 (language-neutral)

All independent applications use the same HTTP host-pull protocol, regardless of branch, language or feature. A newly installed network-enabled managed OCI app with a service port receives a per-installation, per-image random DOMINION_BRIDGE_TOKEN. The host calls the app on its inspected loopback port with Authorization: Bearer token; the app must authenticate every SDK call. No owner API, model key or shell is exposed. Existing legacy v1 apps use the old manual adapter. A user enables v2 after a capability handshake.

GET /dominion/v2/capabilities: {"protocol":"dominion.plugin","version":2,"transport":"host-pull","events":true}
GET /dominion/v2/request: 204 if idle; otherwise {"requestId":"canonical UUID","instruction":"UTF-8 <=16000 bytes","kind":"chat" or "task"}. Keep returning the same immutable request until terminal event is durably acknowledged. Never reuse an ID for another request. No tool or provider selection in the request.
POST /dominion/v2/event: JSON {requestId,runId,status,terminal,answer,error,approvalRequired,tools,eventId}. Status follows host job projection. Only completed jobs include answer; other terminal states are not success. Tools contain bounded actual receipt metadata, not raw results or arguments. Return {"requestId":same,"eventId":same} only after accepting the event; duplicate event IDs must be idempotent, even after a lost response. One active request per application. The host may resend identical events after a network or process failure. Keep the terminal acknowledgement after clearing the active request. No unverified action claims.

Owner chooses chat, web, workspace, or agent scope at connection. Agent scope pins the current registered tool/MCP names. All calls except web_search and http_fetch require a live owner approval, regardless of global auto-approval. The host owns canonical durable job execution. The grant persists across host restarts for the same container and image; a changed image/container requires reapproval. Daily cap 100 requests, max 4 connections. Revocation stops future dispatch, requests cancellation of the current job, and cannot undo completed effects. Model selection is the host's compatible configured model. No shared memory injection by default. No automatic reconnection after replacement. Existing UI Tasks approves tools. The application itself cannot approve them.

This is an implementation contract for other branches, not evidence they support it yet. The transport is host-to-plugin loopback, not a remote mobile network protocol. Device pairing, rich remote UI, streaming, artifacts and voice are application-level features.

Managed OCI images can initialize an empty /data volume from the image's /data directory; existing owner volumes are retained. Packages requiring durable state must initialize /data ownership for their runtime UID in their image. Legacy v1 auto-chat and v2 grants cannot coexist for one plugin. SDK v2 uses the existing owner-approved Tasks UI for effect approval.

## Optional tool-provider capability
An installed program may instead (or additionally) expose GET /dominion/v2/tools, authenticated with the same per-installation bearer. Return {"tools":[{"name":"read_item","description":"Read an item","schema":{"type":"object","properties":{}}}]}. Names are 1–24 ASCII alphanumeric/underscore; at most 64 declarations. Owner previews and registers the exact catalog. The host namespaces names by installation ID and requires effect approval. POST /dominion/v2/tools/call receives {callId,name,arguments,declaration}; the extension must check the supplied declaration against its live tool and return {callId,success,result}. A false result or mismatched ID is not success. The host checks the installed image/container, grant identity and live catalog before dispatch and does not retry HTTP calls. The extension must never interpret tool output as owner instructions. No LLM is needed for registration. Stop/replacement prevents discovery; replacement requires new approval. The contract is generic and does not prescribe any backend protocol.

### Optional settings capability
Owner-only GET and POST /dominion/v2/configuration use the same bearer. GET returns {values:{...},description:"..."}; POST accepts {confirmed:true,values:{...}} and returns redacted values. The extension must validate its own fields, mask stored credentials, and never log submitted secrets. The host refuses configuration changes while that extension's tools are registered. No model invokes this interface.
