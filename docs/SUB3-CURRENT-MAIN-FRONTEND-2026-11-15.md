## 메인 자동 작업 패널과 Rust의 실제 연결

`web/src/components/NativeAgentPanel.tsx` (메인 원본 변경 없음) → `/api/sdk/runs` → `src/api/sdk_runs.rs` → `src/api/jobs.rs::create` → `src/engine/jobs.rs::run_prompt` → `src/engine/native_agent.rs::run` → 독립 `dominion_sdk::Kernel`. 새 모델 하네스나 별도 실행 루프를 만들지 않는다.

| 메인 화면의 실제 동작 | 서브3 연결 |
|---|---|
| 작업 시작·검증 명령 | `jobs::create` 입력 검증·보관 → SDK의 정확한 `shell_exec` 사후 검증 |
| 작업 목록·상태·토큰 | `Store.job` 및 `nativeState`, `nativeModelUsage` 실측값으로 투영. 미보고는 미확인 |
| 1회 도구 승인 | 현재 작업·세션·승인 ID·실제 생존 승인 대기자가 모두 일치할 때 `approvals::resolve_approval` 호출. 고아 승인/중복 승인 거부 |
| 중단 | `jobs::cancel`에서 실제 작업 및 실행 중 세션 취소 |
| 안전한 재개 | 원래 커널의 동일 작업 스냅샷, 미확정 모델/도구 호출 없음, 사용자 취소 없음 조건 검사. 새 모델에 임의 재전송 금지 |
| 미확정 도구의 수동 확인 | SDK `Snapshot::reconcile_tool_observation`: 도구 1개만, 확정 전 유료 모델 호출이 없어야 함. 사용자 관찰은 **실패/미검증 영수증**으로 저장; 종료된 원본 실행을 성공으로 둔갑시키지 않음. 체크포인트를 `interrupted`로 바꾼 뒤 화면의 재개 버튼을 통해서만 다시 실행 |
| 수동 확인 후 새 파일 수정 | 실제 읽기 도구의 영수증이 먼저 생겨야 다음 부작용 도구 실행 가능. 이미 적용했다고 확인한 정확히 동일한 도구/인수 중복 호출 금지 |

유료 제공자의 네트워크 전달 여부가 불명확한 경우는 **수동 확인 버튼으로 해결할 수 없는 상태**이므로 Rust SDK가 재전송을 거부한다. 기존 작업을 그대로 되풀이해 청구서를 중복 발생시키지 않는다.

## 프런트/엔진 기능의 경계

서브3 API/TypeScript SDK에는 고급 토큰 예산, 품질 하한 모델 비용 라우팅, 캐시 단가 및 세부 사용량 필드가 있지만, 이 단계에서는 **메인 원본 프런트에서 존재하지 않는 UI를 새로 추가하지 않았다**. 화면이 실제로 제공하는 사용 동선(시작·결과·승인·중단·재개·확인)만 Rust 구현과 연결한다.

프런트 전체 빌드와 인터페이스 회귀 테스트, Git blob 일치 및 임시 산출물 점검을 별개로 수행한다. 로컬 브라우저 수동 클릭과 상용 제공자 실청구 금액 측정은 집중 테스트와 구분한다.

## 자동 작업 화면의 기존 메뉴 동작 보강

- **모델 자동 선택:** `NativeAgentPanel`에서 `providerId`를 생략해도 서버가 기존 활성 모델 중 **네이티브 도구 호출이 가능한 모델**을 선택한다. CLI/레거시 호환 전용 모델은 제외하며, 적격 모델이 없거나 명시적으로 선택된 모델이 호환되지 않으면 **작업 대기열 생성 전에 HTTP 400**으로 설명한다. 프런트의 AI 모델 선택 항목과 Rust 모델의 실제 실행 능력을 일치시킨다.
- **자동 작업 목록:** `jobs::create`가 `input.clientSurface=native_agent_panel`이라는 제한된 출처를 보존하고, `GET /api/sdk/runs`는 해당 출처의 작업만 반환한다. 다른 화면이 만든 채팅/자동화 프롬프트 작업의 기록은 삭제·수정하지 않으며 기본 작업 목록에 섞지 않는다. 기존 출처 표시가 없던 작업은 공개 `/api/jobs`에서 보존된다.
- **실제 실행 표시:** 메인 패널이 사용하는 마지막 4개 이벤트는 기존 완성된 이벤트 영수증 또는 Rust SDK의 **실제 완료된 도구 영수증 / 현재 write-ahead in-flight 모델·도구**에서 조합한다. 임의 타이머 진행률이나 도구 성공 가상 기록은 만들지 않는다.
- **실행 상태별 버튼:** `in_doubt`(적용/미적용 확인)는 미확정 도구 호출 **정확히 1개이고 모델 전송이 미확정이 아닐 때만** 응답한다. 한도 초과는 `exhausted`, 불안전한 재개 상태는 `denied`, 실제로 복구 가능한 상태만 `interrupted`로 응답해 메인 화면에 작동하지 않는 ‘재개/확인’ 버튼이 나타나지 않도록 한다.

메인 `web/` 파일은 **한 줄도 수정하지 않았다.** 백엔드 API 응답과 Rust 실행기만 메인 UI에 맞췄다. 정상 기능, API/SDK 고급 설정과 기타 화면은 유지한다.
