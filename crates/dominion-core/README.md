# DOMINION 공통 Rust 하네스

`dominion-sub4`의 `5cc47bb782d77273c4d00fed6536f9a2b84aa447`에서 실행 상태, 저널, 도구 스키마 검증, 읽기 전용 정책, 문맥 투영 알고리즘을 가져왔습니다. 서브4의 별도 HTTP 서버와 JSON 제품 저장소는 가져오지 않습니다.

- `domain.rs`: 네이티브 실행 상태와 부모·자식 관계.
- `journal.rs`: 정확한 호출·인자를 실행 전에 기록하고 결과와 함께 해제. 읽기 배치와 불명확한 쓰기의 복구를 구분합니다.
- `tool_schema.rs`: 모델에게 제공한 스키마를 기준으로 실행 전 인자를 검사합니다.
- `hosted.rs`: 제품에 내장되는 Rust 진입점. 모델 호출 상태, 예산 승인, 도구 배치, 완료 조건을 관리합니다. 제공자·도구·저장소는 Rust 어댑터입니다.
- `budget.rs`: 메인에서 검증된 공유 예산 장부를 공통 코어로 옮겼습니다. 병렬 제품 작업도 부모의 같은 예산을 사용합니다.
- `context.rs`: 서브4의 문맥 투영 알고리즘을 보존합니다. 제품의 기존 제공자별 캐시·연속 대화 처리를 임의로 대체하지 않습니다.

메인은 `ChatKernelJournal`로 체크포인트를 기존 SQLite `execution` 레코드에 저장합니다. 병렬 프로그램·절차·결정적 작업은 같은 SQLite의 `native_frame` 자식 실행으로 기록합니다. 파일 결과와 외부 효과의 실제 증거는 기존 `execution_operation`이 소유합니다.

채팅·그룹·작업·워크플로·RSI의 기존 제품 정책은 메인 어댑터에 남습니다. `/api/sdk/runs`도 같은 경로를 호출하며, 공통 모델 실행과 SQLite 체크포인트를 사용합니다. 모델·인증·승인·기억·학습·영상 기능과 React 프론트는 기존 제품 구현을 사용합니다.

이 크레이트는 다른 에이전트 SDK에 의존하지 않습니다. 운영 진입점은 메인의 `src/bootstrap.rs` 하나입니다. 서브4의 모든 제품 코드를 옮겼거나, 실전 모델의 성능·비용이 개선됐다고 주장하지 않습니다.

## 2026-11-20: 코어 / 알고리즘 / 게이트웨이 분리

- **`dominion-core`**: `runtime_port::Host`, `Context`, `Flow`, `model_call`, 스냅샷·예산·취소·권한·저널 계약. 실행 순서 선택 알고리즘 없음.
- **`dominion-algorithms`**: 기존 단일 `Engine::drive` 실행 루프와 그 회귀 테스트를 독립 크레이트로 이동. `dominion-core`에만 의존.
- **`dominion-rust`**: CLI/HTTP/SSE/데스크톱 진입점과 SQLite/도구/모델 호스트 어댑터를 조립하는 제품 게이트웨이.

코어가 알고리즘을 가져오지 않으므로 단방향 Cargo 의존성이 유지됩니다.
